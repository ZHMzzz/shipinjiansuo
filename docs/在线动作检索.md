# Qwen 在线动作片段检索

> 本文保留此前实现与实测记录。当前语义、参考图及图文检索已统一使用 Qwen 片段索引，上传只计算人脸与 Qwen 特征；以 [Qwen 统一检索](Qwen统一检索.md) 为准。
## 使用

打开 http://127.0.0.1:9670/mvp/，选择「07 动作片段」。输入任意中文描述，点击开始检索；输入不会映射到预设类别或预存结果，而是交给 Qwen 实时编码。卡片显示视频、相似度与起止时间，同一视频可以出现多个片段。点击卡片从片段起点播放，可继续查看前后文。

「05 视频库与上传」中的新视频自动建立动作索引。任务变成「已入库」时，语义、物体、人脸（如果检测到）及动作处理均已完成。视频卡片显示动作窗口数。旧视频在升级后自动补建；补建和新上传串行进行，不相互覆盖版本。动作入口显示索引覆盖数、补建进度和失败原因，失败可重试。普通上传失败需从对应任务重试。

当前已入库 18 个视频、37 个动作窗口。可试：

- 「有人在仓库里突然失去平衡倒在地上」→ `动作定位_串接测试24秒.mp4` 的 16–24 秒。
- 「一个人在室内测量墙面」→ 同一视频的 0–8 秒。
- 「有人越过户外的金属围栏」→ `围栏翻越_户外短片.mp4`。

这些示例是验证时实际输入的查询，用户可以自由改写；效果取决于模型和素材。当前没有经过标定的最低相似度门槛，无对应事件时也可能返回低相关候选。

## 数据链路与源码

模型复用 WISE 原有 `wise/src/wise/feature/qwen3vl.py` 中的 `Qwen3VLEmbeddingFeatureExtractor`。沿用上次添加的精度/像素配置：MPS、FP16、总像素预算 1,048,576，不编译、不微调。

新增的 `scripts/action_search.py` 承担以下逻辑：

1. 从 WISE 元数据库读取视频 ID、路径和时长。
2. 以 8 秒窗口、4 秒步长覆盖整段视频，最后一个窗口到达末尾就停止。例如 24 秒视频的窗口为 0–8、4–12、8–16、12–20、16–24 秒。
3. 每窗口均匀抽取 16 帧。只给编码器输入画面，不输入文件名、人工标签或预期答案。短视频允许重复采到同一帧。
4. 用 Qwen 多帧接口生成归一化向量，保存对应视频 ID、起止时间。已有视频复用向量，只计算新增视频。
5. 建立独立的 FAISS `IndexFlatIP` 动作索引。查询时，同一模型实时编码完整中文描述，按内积排序，抑制同一视频高度重叠的近重复窗口。
6. 返回 `/demo/media/<id>#t=<start>,<end>` 和 WISE 缩略图地址。前端明确使用 `ts` 跳转；中点 `thumbnail_ts` 只用于预览，避免错误地从缩略图时刻开始播放。

动作索引放在每个已发布项目版本内的 `action-index/`：

- `metadata.json`：模型与窗口配置、媒体清单、片段列表。
- `vectors.npy`：与片段列表同序的向量，供增量合并。
- `index.faiss`：在线检索索引。

这里新增的是 Demo 的动作管理与查询服务，不是让原版 WISE `/demo/` 页面自动多出动作模式。编码器继续使用 WISE 源码；滑窗入库、版本校验和新页面由本项目实现。

`scripts/server.py` 复用同一个按需加载的 Qwen 实例，不为每条查询重载模型。后台动作提取每完成一个窗口就释放查询锁，使在线查询能穿插执行。在线模型推理与版本发布共享锁；原有 WISE 入库子进程仍可能与查询争用机器资源，所以忙时延迟会增加。

`scripts/ingestion.py` 在 WISE 三路处理之后调用动作索引构建。发布前校验视频清单、全部窗口计划、向量数量和索引维度；动作索引随 WISE 项目一起原子切换。失败保留当前在线版本。启动时检查覆盖：已有完整索引直接使用；缺失或损坏的动作索引在项目副本中补建，不修改正在提供查询的版本。

## API

- `POST /mvp-api/actions/search`：表单 `query`（1–500 字符），`limit`（1–50，默认 20）；返回真实查询向量检索结果及时间范围。
- `GET /mvp-api/actions/status`：当前已发布覆盖数、后台进度、模型是否加载及配置。
- `POST /mvp-api/actions/retry`：安排检查/补建当前视频库动作索引。
- 继续使用 `/mvp-api/uploads`、`/mvp-api/jobs`、`/mvp-api/videos`；不需要额外操作才能让上传的视频参加动作查询。

模型加载前及各次动作推理前检查整机可用内存，低于 2GiB 时返回可重试错误；设置 MPS 进程分配比例 0.55。这是基础资源保护，不是整机内存的严格上限。模型使用本地缓存，启动默认离线。

## 实际验证

新增两条素材通过正常上传 API 完整处理，未直接向正式索引注入实验向量：

| 素材 | 长度 | 新增动作窗口 | 上传登记到完成耗时 |
|---|---:|---:|---:|
| 动作定位_串接测试24秒.mp4 | 24 秒 | 5 | 92.66 秒 |
| 围栏翻越_户外短片.mp4 | 1.4 秒 | 1 | 38.46 秒 |

以上耗时包含转码、子进程加载原有三模型、三路帧特征、Qwen 动作特征和索引发布，不等于纯 Qwen 提取速度，不能按视频时长线性外推。

24 秒素材是为验证时间跳转而人工串接的测试文件：0–8 秒为戴安全帽的室内工人，8–16 秒为原背包行走素材，16–24 秒为仓库模拟摔倒。它不是连续监控事件。源片、时间映射、哈希记录在 `data/test-fixtures/manifest.json`，原素材来源见 `experiments/action-search/manifest.json` 与 `docs/组合查询与动作试验.md`。

三条自由中文查询均以预期视频及窗口为第一名。热模型查询连同缩略图/字节范围检查，本轮约 0.06–0.15 秒；另一次查询约 0.63 秒，并行上传时浏览器记录约 1.17 秒。重启后的首次查询含模型加载约 5.45 秒，其中模型加载约 5.14 秒；不是所有情况下都小于 3 秒。

Chrome 实际点击摔倒第一条结果：播放器从 `currentTime=16` 开始，随后正常播放到 24 秒，`readyState=4`，无媒体错误。重启服务前后 `projects/demo` 指向、三个动作索引文件 SHA-256 完全相同，18 个视频、37 个窗口仍可查询。已有完整索引时重启不会重新抽取动作特征。

21 项单元测试通过，覆盖短片/长片/尾窗、增量向量保留、未完成发布拦截、损坏或错配索引、任意查询传给编码器、非零时间返回、近重复抑制、补建失败保留原库，以及原有上传/组合查询测试。原有四类检索及组合查询回归通过。串接视频包含原背包画面，所以组合查询验证允许该已知副本的 8–16 秒命中，同时仍要求原背包视频处于前列，没有更改检索结果排序。

## 当前边界与维护

- 这是已入库视频的在线查询，不是实时摄像头流分析。上传先离线处理，完成才参与检索。
- 8 秒语义窗口不是精确事件边界；短动作、远处目标、遮挡及复杂时序仍可能误检或漏检。
- 「没有佩戴安全帽」仍存在前期测到的明显误检，本次没有增加专用安全帽检测器。新增接入链路不等于改善此类模型能力。
- 原版实验回放仍在 `/mvp/actions.html`；在线查询入口是主界面的「07 动作片段」。
- 仅在当前小视频库验证。每次入库仍复制版本并重建 FAISS，历史版本保留，占用磁盘会增长。
- 模型配置在 `scripts/action_search.py:SETTINGS`。修改精度、像素预算或窗口参数后需重启，由后台按新配置完整补建，不能混用不同配置的向量。
- 缓存已下载。若迁移机器或清除了 Qwen 缓存，先联网恢复指定权重，再启动服务：

```sh
source scripts/env.sh

```
