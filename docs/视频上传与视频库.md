# 视频上传、处理进度与视频库

> 本文前半部分描述当前上传与视频库；末尾验证记录保留当时行为与数据。首次部署见 [安装与运行指南](首次安装与运行.md)，当前检索行为见 [README](../README.md)。

入口：http://127.0.0.1:9670/mvp/，点击图库标题旁的「新增视频」。

## 当前批量上传入口

主页面点击「新增视频」，可一次多选或拖入多个视频，也可继续追加选择。清单支持逐个移除和清空；单文件仍限制 1 GB，超限文件会提示并跳过。点击「上传 N 个视频」后按顺序传输，分别显示每个文件的结果；失败不会阻断后续文件，可单独或批量重试，已提交成功的文件不会再次发送。后台处理状态在「最近上传」查看。

关闭上传弹窗不会中断传输；传输期间请保持网页打开，不要刷新。文件提交成功后交由后台继续处理。

## 使用流程

1. 选择 MP4、MOV、MKV、AVI、WebM 等视频，单个最大 1GB，点击「上传 N 个视频」。
2. 上传传输进度和后台处理进度分开显示。后台阶段依次为检查视频、转码、提取 OWLv2 物体与 InsightFace 人脸两路帧特征、构建 WISE 索引、建立 Qwen 片段索引、加入视频库。
3. 状态变为「已入库」后，下方列表自动刷新，点击卡片或任务上的「播放视频」即可从头播放。可按文件名筛选。
4. 新素材已参与查询，包括「自然语言」中的场景与动作查询；姓名检索仍需要先登记对应人物照片。没有检测到人脸的视频仍可用于其他检索，不会自动创建人物登记。

关闭页面不取消后台任务。电脑和服务需要保持运行。服务重启后保留任务历史；排队任务继续处理，尚未发布的中断任务显示可重试。重复上传同一内容返回已有任务；如果该任务失败，使用「重试处理」。

## 原有能力与新增代码

复用 WISE 的抽帧、OWLv2/InsightFace 特征、FAISS 索引、检索和媒体播放接口，并写入 Qwen 片段索引；SigLIP 已停用。新增代码负责工作流和管理界面：

| 文件 | 职责 |
|---|---|
| `scripts/ingestion.py` | SQLite 持久队列、SHA-256 去重、ffprobe 校验、FFmpeg 转码、后台串行任务及失败恢复 |
| `scripts/extract_frames.py` / `scripts/frame_acceleration.py` | 入库专用加速入口、OWLv2 fast/FP16 与 InsightFace CoreML；不安装到查询进程 |
| `scripts/server.py` | 上传/任务/视频库 API、索引完整性检查、在线服务切换 |
| `ui/maintenance.js` / `ui/catalog.js` | 批量上传进度、任务轮询、列表刷新和筛选 |
| `ui/catalog.css` / `ui/video-player.js` | 图库与弹窗样式、原片播放与压缩版回退 |
| `scripts/manage.py` | 停止时等待进程退出，避免立即重启时端口仍被占用 |

### 为什么处理完就能检索

上传文件先转为最长边 640 的 H.264 MP4；存在音轨时转成 AAC，便于浏览器播放。当前只索引视频画面，不做音频语义检索。

每个任务复制当前 WISE 项目为独立版本，经 `scripts/extract_frames.py` 对新上传目录执行 WISE 特征提取。新视频每秒 2 帧提取 OWLv2 物体、人脸两路特征与缩略图；入库端默认启用快速 CPU 预处理、实际 FP16 OWLv2 权重及 InsightFace CoreML。随后 `create-index --overwrite` 用新旧特征重建 FAISS 索引。Qwen store 在帧提取和建索引期间暂存并在 finally 恢复，避免自动发现后按帧重复计算。之后按 8 秒窗口、4 秒步长、每段 16 帧编码新增 Qwen 片段，直接写入同一 WISE 项目的元数据、特征文件与检索索引，不另建 action-index。查询端不使用入库加速适配。

发布前检查新视频的元数据、语义特征与缩略图，并核对各模型索引中的向量数与数据库一致。动作索引还需与该版本的全部视频及窗口计划完全一致；动作处理失败时，新视频不会部分发布。随后在查询互斥锁内加载新项目和搜索服务，原子切换 `projects/demo` 符号链接及在线依赖。提取期间旧索引继续服务，最终切换可能短暂等待。已完成才显示 100%；处理失败不会把半成品加入当前库。

处理百分比是阶段估计：转码读取 FFmpeg 时间进度，特征提取读取 WISE 已处理帧数；模型加载、复制项目与索引构建阶段可能停留一段时间，并非卡住。

### 数据存放

- `data/ingestion.sqlite`：任务、原文件名、内容哈希、处理状态、视频 ID。
- `data/uploads/<任务ID>/source.*`：原始上传文件；主页面优先播放，分辨率和大小也由此读取。
- `data/uploads/<任务ID>/prepared/*.mp4`：用于索引、缩略图和原片播放失败时回退的转码文件，不能单独移动或删除。
- `projects/releases/<版本ID>/demo/`：该版本的 WISE 元数据、特征、缩略图和索引。
- `projects/releases/<版本ID>/demo/store/hf/Qwen/Qwen3-VL-Embedding/2B/`：原生 WISE Qwen 特征及搜索索引；片段时间记录在 WISE 元数据中。
- `projects/releases/<版本ID>/demo/qwen-encoding.json`：Qwen 编码设置及媒体签名，不重复保存向量。
- `data/model-cache/frame-acceleration/`：入库 CoreML 的固定形状模型副本及编译缓存，原模型保持只读；停止正在运行的入库任务后可清理并重建。
- `projects/demo`：指向当前已发布版本；初始版本保存在 `projects/releases/initial/demo`。
- `logs/upload-<任务ID>.log`：转码和 WISE 处理日志。

当前自动保留活动版本和上一发布版本，回收发布记录明确列出的更早版本；未知目录和未发布草稿不自动删除。清理失败会重试，见 [版本保留策略](adr/0008-retain-two-published-releases.md)。构建期间需额外容纳一份完整索引，每次上传仍重建 FAISS，当前面向小规模演示。

## 初版上传验证（历史记录，非当前功能清单）

原始 14 个视频之外，使用官方 Kinetics-6 包的 `coughing/ADHjOYdb450_000002_000012.mp4` 截取新的短片，经真实上传 API 完整入库。

- 3 秒无音轨视频约 35 秒完成处理（包括子进程模型加载），增加 6 条语义向量、529 条物体向量、6 条人脸向量。
- 在 15 个视频的库中，中文描述「穿橙色衣服的小孩坐在地毯上」召回新视频，原始帧结果排名第 5；图片物体和人脸查询第一条均来自新视频。该排名只证明链路可用，不等于独立准确率评测。
- 新截图溯源第一条来自新视频，定位到 1.1 秒；视频字节范围播放与缩略图返回正常。
- 重复上传返回同一个任务；伪装成 MP4 的无效文件显示解码失败，当前索引和视频数量不变。
- 原有中文、背包图片、截图溯源、姓名检索回归通过，记录见 `logs/verify-regression.log`。
- 另上传同一来源的 2 秒带音轨片段，约 47 秒完成，保留 AAC 音轨并以 AV 类型入库。当前共 16 个视频、41,453 条特征。服务停止再启动后，16 个视频、3 条任务记录仍在，带音轨视频返回 HTTP 206 字节范围播放；两段新视频仍可由中文查询召回。记录见 `logs/upload-restart-verification.json`。
- Chrome 页面已看到自动更新的列表、已完成/失败任务和新视频实际播放画面。浏览器扩展未授权自动选择本地文件，所以完整上传由真实 HTTP 接口验证；没有修改浏览器权限。

这些短片耗时包含模型加载、转码、复制项目与建索引固定开销，不可按视频秒数直接线性外推。界面中的「无效文件测试.mp4」是刻意提交的失败用例。

自动验证入口：`source scripts/env.sh` 后运行 `python -m pytest tests/test_ingestion.py -q`。上传联调记录在 `logs/upload-verification.json`；`scripts/verify_upload.py` 针对本次固定测试素材，运行会尝试重复上传及一个无效文件测试，不是通用性能基准。
