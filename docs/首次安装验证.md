# 首次安装验证记录

验证日期：2026-10-30。操作指南见 [首次安装与运行](首次安装与运行.md)。

## 环境与隔离方式

Apple M5、32 GB 统一内存、macOS 26.5.1、原生 arm64 Python 3.11.15。Homebrew 的 Python 3.11、Node 22、libmagic 和 Command Line Tools 已安装。

从 Git 已跟踪文件导出一份独立源码（基线 `a5bea11`，叠加本次安装脚本与锁文件修正），在独立目录创建 `.venv/`、`.media-runtime/`、SDPA 运行时、前端构建和视频索引。没有复制原项目的虚拟环境、索引、上传视频或人物数据库；检查了 editable WISE 安装指向隔离目录。

复用了本机包下载缓存和用户目录中的 Hugging Face、InsightFace 模型缓存。`warm_models.py` 以联网模式执行并完成真实模型预热，但本次不是清空用户缓存后重新下载全部模型的测试，也不是一台刚安装 macOS 的机器。

为保留原有 9670 服务，真实应用使用同一 `server.app` 在 `127.0.0.1:19670` 启动。安装、建库脚本直接执行；`start.sh` 的前置失败分支单独检查。没有声称本轮通过 `start.sh` 在默认 9670 端口完整启停了新实例。

## 发现与修正

- 原 FFmpeg 锁文件第一行是本机导出提示，缺少 `@EXPLICIT`。在空目录对其执行 micromamba 解析，以及首次安装实际执行到该步骤时，均以退出码 139 失败。改为带注释和 `@EXPLICIT` 的固定包 URL 清单后，63 个包成功解析并安装，保留原来的包版本。
- `setup.sh` 增加 `--check`，检查平台、Python、Node、libmagic、开发工具及 micromamba，展示安装阶段；安装后检查 MPS、libmagic 和 Torchaudio 的 FFmpeg 动态库。
- `start.sh` 在缺少环境、前端构建或初始索引时返回明确的安装／建库指令，不再只启动一个随后报错的后台进程。
