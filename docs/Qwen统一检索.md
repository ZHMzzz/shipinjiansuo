# Qwen 片段统一检索

2026-10-27：按用户要求，先提交现有代码（`632b261`），再将正式检索与入库中的 SigLIP、OWLv2 替换为已有 Qwen 片段索引。人脸登记和 InsightFace 检索保留，不增加 Qwen 帧索引。

## 当前链路

| 入口 | 查询与结果 |
| --- | --- |
| 中文语义 | Qwen 文本向量检索已有视频片段，每个视频保留最强片段 |
| 参考图 | Qwen 图片向量检索视频片段，不输出物体框 |
| 图文组合 | 图片和文字放入同一个 Qwen 输入联合编码 |
| 截图溯源 | Qwen 按视频召回前 5 个候选，灰度相关性约 10Hz 细化时间；每个候选仍最多扫描前 60 秒 |
| 姓名检索 | 原人物库与 InsightFace 向量；原登记无须重做 |
| 人物＋场景 | 先以人脸相似度作身份门槛，再以包含该人脸时刻的同视频 Qwen 片段作场景排序；RRF 融合 |
| 动作片段 | 同一 Qwen 索引，可返回同视频的多个片段；原可选 Qwen Reranker 保留 |

查询端图片与文字继续使用已有视频向量的 user-only 模板，不额外插入 system 指令。`action-index` 目录名和 SETTINGS 保持兼容；8 秒窗口、4 秒步长、16 帧抽样、FP16 / MPS 配置不变。负向文本以 0.2 权重减向量并归一化，仅影响排名。

片段相关不代表人物与场景在同一帧同时出现；相似度不是概率。短暂小物体、遮挡、精确外观和事件边界仍可能漏检。截图精排的 60 秒上限与强裁剪局限保留，未宣称完整长视频溯源能力。

## 索引迁移与上传

`scripts/qwen_project.py` 在启动时检查项目。旧项目必须已有完整 Qwen 索引才能迁移；缺失时拒绝发布，保留原版本。迁移持有入库锁，复制项目到新 release，删除 SigLIP/OWLv2 的 WISE 向量、关联旧框记录和 store 资产。逐文件校验 Qwen 索引、人脸资产和缩略图哈希，并核对媒体、人脸数据库行，成功才原子切换 `projects/demo`。原 release 不删除。重复启动不重复迁移。

移除 store 资产是必要步骤：WISE 的增量提取会从已有项目发现编码器，单纯改前端或请求参数无法停止旧模型入库。

新上传流程：转码 → 2fps InsightFace → 人脸索引 → 仅新增视频的 Qwen 片段 → 完整性验证 → 发布。无脸视频允许入库，只要求其 Qwen 片段与缩略图完整；人物能力显示“未检出人脸特征”。旧 Qwen 向量不重算。旧模型源码、权重缓存和历史实验保留，但不在正式链路加载。

主要 API：`POST /mvp-api/search` 接收 `query`、`negative`、`photo`、`limit`，返回 `score_kind=segment` 和片段时间；人物、动作、上传 API 路径保持不变。原 WISE `/demo/` 只暴露保留的人脸索引，通用检索使用 `/mvp/`。
