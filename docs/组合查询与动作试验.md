# 组合查询与 Qwen 动作检索试验

> 本文保留此前实现与实测记录。当前语义、参考图及图文检索已统一使用 Qwen 片段索引，上传只计算人脸与 Qwen 特征；以 [Qwen 统一检索](Qwen统一检索.md) 为准。
## 已接入的在线查询

图文组合、负向查询和人物＋场景均连接实际模型与当前视频库，没有模拟结果。现有视频无需重新提取特征。

| 入口 | 数据流程 | 边界 |
|---|---|---|
| 06 图文组合 | 参考图和文字 → WISE SigLIP2 嵌入融合 → 现有语义索引 | 整帧相似性，不是严格物体身份及场景逻辑判断 |
| 降低这些内容的排名 | 负向文字向量按配置权重参与融合 | 不保证完全排除，负向权重沿用 WISE 配置 |
| 04 人物姓名＋场景 | 姓名取已登记向量 → 人脸检索 → 门槛筛选 → 约束同一视频同一时间帧 → SigLIP2 场景检索 → WISE RRF 融合 | 人物门槛是硬筛选；场景仍是软排序，不能仅凭返回结果断言场景成立 |

`scripts/combined_search.py` 调用 WISE 搜索服务和 `fuse_face_text_frame_results`。原始 WISE 联合查询通过图像输入启动；我们的姓名库已经保存人脸向量，因此适配为直接使用登记向量，并在场景查询前过滤不满足人脸门槛的候选。没有直接相加两个不同模型的人脸与文字向量。

页面显示「融合排序分」以及独立的「人脸」「场景」分数。融合分数来自 WISE 基于排名的输出，不能用 0.45 人脸门槛再次过滤，也不是概率。

真实验证：背包图＋「在街道上」第一名是 `backpack-street.mp4`；＋「在室内」第一名是 `backpack-walking.mp4`。负向描述会改变分数/排序。演示人物A＋「坐在汽车里」返回登记人物所在视频；人脸门槛 1.0 返回空结果。Chrome 已操作验证图文、负向和人物场景结果。

验证代码：`scripts/verify_combined.py`；原有四类检索回归记录：`logs/verify-regression-combined.log`；同帧约束及身份门槛测试：`tests/test_combined_search.py`。

## Qwen 测试方法

模型：[Qwen/Qwen3-VL-Embedding-2B](https://huggingface.co/Qwen/Qwen3-VL-Embedding-2B)，下载快照 `9f2f7e710d6d81056aa5c0a4f04764fec6bb7bda`，约 4.26GB 权重。推理复用 WISE 的 `Qwen3VLEmbeddingFeatureExtractor`，未训练或微调模型。

设备为 Apple M5 / 32GB；现有 Demo 和用户其他应用保持运行。所有数字是这次实际负载下的测量，不是专用空闲机器基准。

实验素材位于 `experiments/action-search/videos/`，共 10 段，合计约 55.92 秒。每段最长 8 秒，均匀抽 16 帧，一次编码一个片段，建立独立的 FAISS Flat 索引。当前试验是短片级召回，不是长录像滑窗边界定位评测。

手动检查了原片抽帧，预先记录标签与来源。模型只读取画面和查询文字，不读取文件名、标签、素材描述。使用 6 组中英文查询（共 12 条），保留所有原始排名，不按预期答案重排。

素材来源和用途：

- [Tenor 翻越木围栏片段](https://tenor.com/view/fence-vaulting-parkour-shortcut-chase-gif-12946237)：影视画面，分为站立和翻越两个不重叠短片。
- [Tenor 金属围栏翻越片段](https://media.tenor.com/Rc5UK-RgCNwAAAP1/jump-fence.mp4)：户外短片。
- [Fall_detection 示例](https://github.com/aayushgzip/Fall_detection/blob/main/fall.mp4)：仓库模拟摔倒，分为摔倒前正常行走和摔倒过程。人物头部裸露，作为未佩戴安全帽的可见外观样本；未确认该地点的安全帽要求，不能称为已确认违规。
- [DetectConstructionSafety 示例视频](https://github.com/rahilmoosavi/DetectConstructionSafety/tree/master/videos)：三个佩戴安全帽场景，包含蹲下作业，用于安全帽和摔倒对照。
- 原有 Pexels 背包行走、WISE 官方 Kinetics 坐在汽车里片段，作为正常活动对照。

来源、裁剪起点、人工标签和 SHA-256 见 `experiments/action-search/manifest.json`。这些是公开演示/研究素材，不是统一监控机位数据集；素材版权仍归原权利人，没有据此授予商业再分发许可。两个来源各切出动作/对照片段，样本并非全部独立。

## 两种配置

- 原始配置：非 CUDA 默认 FP32，WISE 默认总像素预算 7,864,320；16 帧。
- Mac 轻量配置：FP16，总像素预算 1,048,576；仍使用 16 帧。同时调整了精度和分辨率，因此速度差不能单独归因于半精度。

为此给 `wise/src/wise/feature/qwen3vl.py` 增加 `dtype` 与 `max_total_pixels` 配置项，默认值保持上游行为。轻量配置降低画面细节，远处小安全帽等目标可能更难区分。每段实际模型输入网格与 token 数保留在运行 JSON 中。

实验在独立子进程执行；每 0.2 秒采样进程 RSS、系统可用内存及交换区用量，每约 0.05 秒采样 Metal 分配。设置了单进程 Metal 预算、系统剩余内存保护与超时。没有提高系统内存限制。

RSS 与 Metal 内存口径不同，不能直接相加。Metal 驱动分配包含缓存；它不是整机总内存，也不是“模型权重大小”。已有交换区存量不等于这轮试跑新产生的交换量。

## 实测结果

| 指标 | Mac 轻量配置 FP16 | 原始精度/像素配置 FP32 |
|---|---:|---:|
| 素材 | 10 段 / 55.92 秒 | 同一批素材 |
| 模型加载 | 4.68 秒 | 7.44 秒 |
| 视频特征提取合计 | 18.75 秒 | 90.87 秒 |
| 单片段提取中位数 | 1.82 秒 | 8.58 秒 |
| 全实验进程耗时（含加载、解码、12 条查询） | 30.32 秒 | 106.90 秒 |
| 单次查询中位数（模型已加载） | 0.062 秒 | 0.104 秒 |
| Metal 驱动分配峰值 | 5.16 GiB | 11.59 GiB |
| Metal 活跃张量分配峰值 | 4.16 GiB | 9.05 GiB |
| 进程 RSS 峰值（不同口径，不与 Metal 相加） | 4.99 GiB | 3.16 GiB |
| 运行期间整机可用内存最低值 | 6.75 GiB | 3.14 GiB |

FP16 首轮提取为 25.66 秒、全进程 41.78 秒；补充 Metal 采样后的同配置复跑为表中数字。缓存状态和后台负载会影响耗时，不能把最快复跑值作为承诺。FP32 测试期间系统交换区已用量由约 13.47GiB 增至 16.15GiB，这是整机观测，无法完全归因于本模型，但说明当时内存压力较大。两轮均正常结束，未触发保护停止。

查询效果（完整原始排名保存在 JSON）：

| 查询 | FP16 | FP32 | 解读 |
|---|---|---|---|
| 人员翻越围栏 / 英文同义查询 | 两段翻越分别第 1、2 名 | 同样第 1、2 名 | 此批短片能召回目标 |
| 一个人失去平衡摔倒在地 / 英文同义查询 | 摔倒片段第 1 名 | 摔倒片段第 1 名 | 能区分此批摔倒与正常活动对照 |
| 作业人员没有佩戴安全帽 | 第一名是戴帽工人；首个裸头作业样本第 4 名 | 同样首个正例第 4 名，第一名仍戴帽 | 明显误检，两种配置均失败 |
| A worker without a safety helmet. | 第一名仍戴帽；首个正例第 2 名 | 同样第 2 名 | 改成英文也没有解决 |
| 工人佩戴安全帽 | 第 1 名符合标注 | 第 1 名符合标注 | 可召回明显安全帽场景 |
| 工人蹲下作业 | 蹲下片段第 1 名 | 同样第 1 名 | 本次正常动作对照可区分 |

这不能证明复杂动作或时序关系的通用准确率：没有做动作顺序反转测试，也没有与单帧模型建立受控对照。只证明本机能够完成多帧向量提取和这些小样本查询。未戴帽正例主要来自同一仓库素材，数量不足；不能把此测试称为工地安全帽检测评测。

结论：本机适合先用 FP16、受控像素预算做动作片段候选检索，再扩大真实监控样本验证。原始 FP32 能运行，但速度和内存成本较高。安全帽缺失应补充人员/头部/安全帽检测与对应关系，并设置「头部不可见」状态，不能将没有检测到帽子直接等同于未佩戴；本次未增加专用安全帽检测器。

软件环境：PyTorch 2.8.0、Transformers 4.57.6、qwen-vl-utils 0.0.14、FAISS 1.15.1、NumPy 1.26.4。机器和依赖摘要见 `experiments/action-search/summary.json`。

```sh
source scripts/env.sh
HF_HUB_OFFLINE=1 python scripts/benchmark_actions.py --name qwen-fp16 --dtype float16 --pixels 1048576
```
