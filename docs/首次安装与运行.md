# 首次安装与运行

本指南面向从 GitHub 新克隆源码、尚无 Python 环境和视频索引的用户。主入口是「寻帧」视频库：http://127.0.0.1:9670/mvp/ 。当前功能说明见 [README](../README.md)，本次隔离恢复的实测范围见 [安装验证记录](首次安装验证.md)。

## 1. 确认机器与网络

| 项目 | 当前要求与边界 |
| --- | --- |
| 系统 | Apple Silicon Mac，使用原生 arm64 终端；脚本依赖 zsh、MPS、CoreML 和 `/opt/homebrew` 路径 |
| 已验证硬件 | Apple M5、32 GB 统一内存；这不是最低配置测试。其他 Apple 芯片及更小内存未做完整验收 |
| 其他平台 | Windows、Linux、Intel Mac 尚未适配；仅关闭入库加速不能让 Qwen 脱离 MPS 运行 |
| 系统工具 | Xcode Command Line Tools、Homebrew、Python 3.11、Node 22、libmagic |
| 空间 | 需容纳源码及演示素材、两套 Python 环境、FFmpeg、模型缓存和索引。额外视频会持续占用空间；索引构建时还要容纳一份全库副本。安装前用 `df -h .` 检查，不按源码 ZIP 大小估算 |
| 网络 | 首次安装需要访问 GitHub、Python 包源、conda-forge、npm 和 Hugging Face；InsightFace 也会下载模型。后续启动默认离线读取模型缓存 |

在 macOS「终端」运行：

```sh
uname -s
uname -m
xcode-select -p
```

前两项应为 `Darwin` 和 `arm64`。若显示 `x86_64`，先确认不是 Intel Mac 或通过 Rosetta 打开的终端。开发工具未安装时执行 `xcode-select --install`，完成系统安装窗口后再继续。

若没有 Homebrew，请按 [Homebrew 官方安装说明](https://docs.brew.sh/Installation) 安装到 Apple Silicon 默认路径 `/opt/homebrew`。随后执行：

```sh
eval "$(/opt/homebrew/bin/brew shellenv)"
brew install python@3.11 node@22 libmagic
/opt/homebrew/opt/python@3.11/bin/python3.11 --version
/opt/homebrew/opt/node@22/bin/node --version
```

应分别显示 Python `3.11.x`、Node `v22.x`。不要求替换系统 Python 或强制链接 Node；项目的 `scripts/env.sh` 会设置运行路径。仓库已附带 `tools/bin/micromamba`，FFmpeg 6 安装在项目内部，无需另外安装系统 FFmpeg。

## 2. 下载完整源码

```sh
git clone --depth 1 https://github.com/ZHMzzz/shipinjiansuo.git
cd shipinjiansuo
git branch --show-current
./scripts/setup.sh --check
```

默认分支应为 `main`。`--depth 1` 只下载最新版本，适合首次运行，避免拉取旧提交中的大视频和实验产物；以后仍可 `git pull --ff-only` 更新，需要完整开发历史时执行 `git fetch --unshallow`。如果仓库访问需要认证，请使用有访问权限的 GitHub 账号；已配置 SSH 的用户可改用 `git@github.com:ZHMzzz/shipinjiansuo.git`。`--check` 只检查系统前置工具，不下载依赖，也不代表模型和索引已就绪。

`wise/` 是仓库自带的修改版源码，不需要初始化子模块，也不要用 `pip install wise` 代替本项目的安装步骤。使用 GitHub ZIP 下载时，解压后进入包含 `README.md` 的根目录；若执行权限丢失，执行 `chmod +x scripts/*.sh tools/bin/micromamba`。

仓库包含 14 个初始演示视频（`data/videos/`）、参考图、前后端源码、测试与文档。额外的摔倒／火情／抽烟视频集合、临时目录、截图及实验结果不随最新源码包交付，主检索功能不依赖它们。以下内容需要在新机器生成：

- `.venv/`、`.media-runtime/` 和 `data/model-cache/` 中的运行环境及加速缓存。
- 下载到用户目录的 Hugging Face、InsightFace 模型缓存。
- `projects/` 内的索引，以及 `data/people.sqlite`、`data/ingestion.sqlite`。
- 原机网页上传的视频；需要重新上传，人物也需要重新登记。

## 3. 安装依赖、模型和前端

在项目根目录执行，等待命令正常结束：

```sh
./scripts/setup.sh
```

脚本依次完成六步：安装 `requirements-macos.lock.txt`（含本地 `wise/`）；安装锁定的 FFmpeg 6 环境；检查 MPS、libmagic 和 Torchaudio 解码器；下载并预热 InsightFace、OWLv2、Qwen3-VL-Embedding 2B；安装 OWLv2 SDPA 独立运行时；执行 `npm ci` 和前端构建。

终端打印「环境准备完成」才算此步骤完成。首次下载与模型加载可能较久，没有固定耗时承诺。错误出现时先处理错误再重跑；脚本可复用已安装依赖和模型缓存。不要在同目录服务运行期间重装依赖。

需要保留安装日志时，在 zsh 中执行：

```sh
mkdir -p logs
set -o pipefail
./scripts/setup.sh 2>&1 | tee logs/setup.log
```

`pipefail` 确保安装失败不会被 `tee` 的成功退出掩盖。日志是本地产物，不提交 Git。

## 4. 建立初始视频索引

首次安装完成后执行：

```sh
./scripts/index.sh
```

它读取 `data/videos/`，通过 OWLv2 提取物体区域、InsightFace 提取人脸，再建立 WISE 检索索引。不要与在线服务、上传或其他建库命令同时运行。首次 CoreML 编译也可能较慢；等待命令成功退出，不能只看 `projects/` 目录已出现。

这一步还没有完成 Qwen 片段索引；它会在下一步首次启动时后台补建。日常新增视频使用网页的「新增视频」，不需要重新运行 `index.sh`。请保留演示素材目录和视频文件的位置；索引中包含媒体路径，移动项目后应重新验证路径，不能直接复制另一台机器的索引当成新安装。

## 5. 启动并验收

```sh
./scripts/start.sh
tail -f logs/server.log
```

`start.sh` 启动后台进程，打印 PID 只代表已发起启动。日志出现 `Application startup complete` 后，打开 http://127.0.0.1:9670/mvp/ 。`Ctrl+C` 退出 `tail` 只停止查看日志，不会停止服务。

首次启动先加载模型，随后自动在副本中补齐 Qwen 片段并发布。可用另一个终端检查：

```sh
curl --fail --silent --show-error http://127.0.0.1:9670/mvp-api/actions/status
```

正常最终状态包含 `status: "ready"`、`model_loaded: true`、`indexed_videos: 14` 和大于 0 的 `indexed_segments`（尚未添加或删除演示视频时）。`pending`、`building` 表示仍需等待；`failed` 时查看返回的 `message` 和日志，处理原因后可重试：

```sh
curl --fail --show-error -X POST http://127.0.0.1:9670/mvp-api/actions/retry
```

首次验收建议依次确认：

1. 默认视频库出现 14 个视频，缩略图可见，点击能播放。
2. 片段索引 `ready` 后，输入「有人在跑步」或「锅里正在炒蔬菜」，查询能返回结果并跳转播放。排序是模型结果，不用某个固定名次判断安装成功。
3. 清空文字后，选择 `data/queries/` 中的物体参考图，确认纯图片查询有结果；同时填写文字可验证 Qwen 图文联合查询。
4. 「人脸维护」中登记清晰单人照片，再从人名下拉框选择姓名查询。全新安装的人物列表为空是正常现象，登记对象需要实际出现在视频库中才可能命中。
5. 按需上传自己的短视频，任务显示「已入库」后确认图库新增记录。上传后处理期间保持电脑和服务运行。

服务只监听 `127.0.0.1`，同一局域网的其他电脑不能直接访问。此项目没有现成的公网部署或账号权限方案。

## 6. 停止、再次启动和更新

```sh
./scripts/stop.sh
./scripts/start.sh
```

以后无需重复安装或建库。更新源码前先停止服务，确认本地改动已保存，再执行 `git pull --ff-only`；依赖锁或前端源码更新后重新执行 `./scripts/setup.sh`，成功后启动。不要删除 `data/`、`projects/` 或人物数据库来解决普通启动错误。

自动化回归从根目录执行（使用 zsh）：

```sh
source scripts/env.sh
python -m pytest tests -q
node --test tests/test_video_player.mjs
```

这些测试不能代替完整模型下载与真实视频验收；根目录的 `tests` 是本项目测试，省略目录可能收集上游 WISE 的其他测试。`scripts/verify*.py` 中有依赖原开发机人物、上传素材或历史结果的脚本，不作为首次安装的通用验收命令。

## 常见问题

| 现象 | 处理方式 |
| --- | --- |
| `setup.sh --check` 提示缺少工具 | 按提示安装对应 Homebrew 包或 Command Line Tools；确认终端和 Python 都是 arm64 |
| Python 包下载、模型下载超时 | 确认相关源可访问，保留报错与日志；网络恢复后重跑。不要随意升级锁定版本来绕过错误 |
| 提示 `libmagic`、OpenMP 或 FFmpeg 动态库错误 | 使用 `source scripts/env.sh` 后的项目 Python；确认 `setup.sh` 完整成功。不要设置忽略重复 OpenMP 错误的开关 |
| SDPA 运行时缺失或版本不符 | 执行 `./scripts/setup_owl_sdpa.sh`；它只安装独立运行时，不升级主环境的 Torch/Torchaudio |
| 启动提示环境未准备完成 | 先完整运行 `setup.sh`，确保 `wise/frontend/dist/index.html` 已构建 |
| 启动提示尚未建立初始索引 | 先完成 `index.sh`；首次不能直接 `start.sh` |
| 显示“启动中”但网页打不开 | 查看 `logs/server.log`，等待模型预热；进程退出或有 traceback 时先处理错误。PID 提示不是成功验收 |
| 9670 端口已占用 | `lsof -nP -iTCP:9670 -sTCP:LISTEN` 查看占用；只停止自己确认的服务。同一端口一次运行一个实例 |
| 自然语言查询提示索引未就绪 | 检查 `/mvp-api/actions/status`，等待补建完成；失败时检查消息与日志再重试 |
| 模型缓存被删除，离线启动报错 | 停止服务，在 zsh 执行 `source scripts/env.sh`，再执行 `HF_HUB_OFFLINE=0 python scripts/warm_models.py`，完成后正常启动 |
| `/docs` 或 `/openapi.json` 报 Schema 错误 | 上游模型的全局 OpenAPI Schema 有已知兼容问题；用主页面和 `/mvp-api/actions/status` 验收，不把它当作全部检索服务失效 |
| 内存不足、MPS 分配失败 | 关闭其他占内存程序；当前只在 M5 / 32 GB 实测，没有验证小内存最低规格 |

`VIDEO_OWL_SDPA=0` 可回退独立 SDPA 入库后端；必须在建库和服务启动时使用一致配置，例如 `VIDEO_OWL_SDPA=0 ./scripts/index.sh` 和 `VIDEO_OWL_SDPA=0 ./scripts/start.sh`。它不取消 Apple Silicon/MPS 要求，也不重新计算已有索引。其他性能开关见 [README](../README.md)。

模型权重和素材有各自许可；当前 InsightFace 预训练模型按非商业研究使用。使用场景和模型效果边界见 README。历史实验文档描述的是当时版本，不能直接套用其中已移除的截图溯源、重排或独立动作接口。
