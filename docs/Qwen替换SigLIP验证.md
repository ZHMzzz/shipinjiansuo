# Qwen 替换 SigLIP：离线验证

验证日期：2026-10-27。结论：Qwen 2B 可以覆盖本次截图召回、背包类别、图文组合和中文查询样本，但没有证明检索效果普遍优于 SigLIP。现有 Qwen 片段索引是较合理的替换起点；本轮没有证据支持为了替换而立即新增全库 Qwen 帧索引。正式入口尚未切换。

## 范围与方法

冻结当前发布版本 `projects/releases/3cf04e2d55e446e79ab5e0112b2259a4/demo`，共 27 视频、338.56 秒、74 个现有 Qwen 片段。先固定查询与标签，再执行推理。

- 6 张已有视频截图，预期源视频已知。
- 1 张独立背包照片，评估背包类别召回。该照片与视频中的背包不是同一款，不能据此评估同一物品识别。
- 背包图配街道、室内描述，各 3 种表述，共 6 条图文查询。这里只覆盖两个场景意图，并非 6 个独立场景。
- 3 条中文查询：背包行走、跑步、炒蔬菜。
- 串接测试视频 17 的 8–16 秒包含背包素材。仅该时间范围的帧或至少半个窗口与该范围重叠的片段被视为室内背包正例。标签只用于计算指标，不进入模型。

对比四个配置：

| 配置 | 索引与查询方式 |
| --- | --- |
| 当前在线 SigLIP | 正式 `/demo/search`，现有完整帧索引，图片与 2 倍文字向量融合 |
| 对照 SigLIP 帧索引 | 每视频 0.5 秒起、每 2 秒抽帧，共 173 帧；同样融合权重 |
| Qwen 帧索引 | 与对照 SigLIP 使用完全相同的 173 张解码图像；图片最大像素 262,144；官方默认 system 指令，图片与文字联合编码 |
| 现有 Qwen 片段索引 | 74 个已有 8 秒/4 秒步长窗口；查询采用与现有索引一致的 WISE user-only 模板，图文共同编码 |

两种 Qwen 配置的输入模板不同，因此其差异不能全部归因于帧/片段粒度。现有片段索引复用实验只验证当前完整配置，未证明官方模板与旧模板可以任意混用。

离线帧检索采用归一化向量的精确内积扫描，效果等价于 FlatIP 的全量精确排序，但其计时不代表线上 FAISS 服务。按每个视频的最佳命中去重，保存全部视频排序。在线基线沿用最多 100 个原始命中，保存去重后返回结果。各模型分数尺度不同，不能横向比较分数大小。

## 检索结果

下表是目标排在第一名的查询数量。

| 配置 | 截图 6 条 | 背包图片 1 条 | 图文 6 条 | 中文 3 条 |
| --- | ---: | ---: | ---: | ---: |
| 当前在线 SigLIP | 6/6 | 1/1 | 5/6 | 3/3 |
| 同抽帧 SigLIP | 6/6 | 1/1 | 5/6 | 2/3 |
| Qwen 帧索引 | 6/6 | 1/1 | 4/6 | 3/3 |
| 现有 Qwen 片段索引 | 6/6 | 1/1 | 5/6 | 3/3 |

四种配置的全部查询均在前五名内找到预标注目标。这不代表结果列表中没有误检。

具体失败样例：

- 背包图＋“在室内”：Qwen 帧索引第一名是街道背包，目标首次出现在第二名；现有 Qwen 片段索引与 SigLIP 第一名符合场景。
- 背包图＋“一个人背着背包在室内行走”：Qwen 帧索引仍将街道背包排第一。
- 背包图＋“寻找图中这类背包，被人背着在室内行走”：Qwen 帧索引第一名正确；现有 Qwen 片段索引与 SigLIP 都将街道背包排第一、室内背包排第二。

因此，换成 Qwen 联合编码并不会自动消除场景约束错误，也不能假定更长的提示词一定更好。

## 截图时间定位

对四种方法召回的前 5 个视频使用与现有服务相同的灰度画面相关性比对：约 10Hz 扫描，每候选最多 60 秒。

6 张截图在四种配置下均找到正确源视频，细化后的命中时刻完全一致。原截图均由 2.25 秒抽取，命中时间分别为 2.30、2.40、2.1021、2.3023、2.3023、2.64 秒。

5/6 的偏差不超过 0.3 秒；背包行走截图偏差为 0.39 秒，所有配置都有此误差。Qwen 可以替换本批样本的候选召回，但仍需保留画面细化；这里不宣称它直接实现了精确时间定位。细化本身每次约 0.24–0.74 秒，随候选视频组合变化。

## 性能与资源

Apple M5 / 32 GiB，MPS；Qwen FP16，SigLIP 使用现有默认精度。正式 Demo 与其他应用保持运行，模型分阶段在独立进程中加载，不同时常驻两套实验模型。查询输入预先读入内存，模型预热后每条编码 3 次，未启用查询向量缓存。

| 配置 | 图片查询编码中位数（截图组） | 图文编码中位数 | 纯文字编码中位数 |
| --- | ---: | ---: | ---: |
| 同抽帧 SigLIP | 0.027 秒 | 0.051 秒 | 0.025 秒 |
| Qwen 帧索引查询 | 0.538 秒 | 0.615 秒 | 0.044 秒 |
| 现有 Qwen 片段索引查询 | 0.539 秒 | 0.581 秒 | 0.044 秒 |

图文查询编码在本配置下约慢 11–12 倍。以上不含网络、服务排队、图片上传解码和结果序列化；不能直接当作改造后的 HTTP 总延迟。当前在线 SigLIP 图文 HTTP 中位数另外测得 0.058 秒，仅作现状参考。三次重复只能说明本次观测，未作并发、长期稳定性或 P95 评测。

相同 173 帧的编码累计：SigLIP 4.19 秒，Qwen 99.03 秒，约 23.6 倍。包含图像预处理与 GPU 同步，不含视频解码、模型加载、保存或构建 FAISS。Qwen 使用更高像素预算，不能将差异完全归因于模型结构。现有片段索引是复用的，本次没有重测其入库成本。

Qwen 冷模型加载 9.61 秒。SigLIP 本次记录的初始化计时存在延迟加载边界，不用于冷启动比较；复现脚本已显式触发完整模型加载。

| 实验进程采样峰值 | SigLIP | Qwen |
| --- | ---: | ---: |
| Metal 驱动分配 | 2.17 GiB | 5.15 GiB |
| 进程 RSS | 3.32 GiB | 4.38 GiB |
| 模型阶段整机可用内存最低 | 6.40 GiB | 4.38 GiB |

每 50ms 采样，峰值包含模型加载、帧编码及查询。RSS 与 Metal 存在重叠，不能相加；不能把它们解释为改造后整个服务的总占用。Qwen 运行时整机已有交换区用量并有增长，不能全部归因于实验。未触发 2 GiB 可用内存保护。

## 正确性与隔离

- 固定 Qwen 权重版本：`9f2f7e710d6d81056aa5c0a4f04764fec6bb7bda`。
- 下载同版本官方 Embedding 示例，保留 URL、SHA-256。使用相同已加载权重，对一条图文输入分别执行本地适配和官方格式化/预处理/池化：向量余弦 0.99999994，最大分量差 0.00003005。仅验证该输入的一致性，不是全输入等价证明。
- 帧向量检查有限数值、单位范数及数量。查询不读取文件名、标签和预期答案。
- 实验前后正式项目指针、元数据库、动作向量及全部 `.faiss` 文件 SHA-256 一致。
- 服务保持可用，结束时状态 `ready`、27 视频、74 片段。未修改正式模型配置、UI 或线上检索路由。
- 安全帽、复杂否定、同款物体识别、姓名＋场景融合、长视频定位、多人并发和大规模视频库没有在本轮获得充分验证。

## 后续判断

若目标是减少模型种类、统一查询能力，可以基于现有 Qwen 片段索引继续替换开发，并保留截图的画面细化。当前样本的效果接近线上 SigLIP，图文热编码约 0.6 秒。

若目标是通过替换显著提升准确率，本轮结果不支持这一承诺。还需独立图片、更多场景及小目标/短暂出现对象的验证。现阶段不建议仅因为“Qwen 更大”就额外建立全库帧索引；本次帧索引既增加入库成本，也没有取得更好的图文表现。

## 复现与证据

```sh
source scripts/env.sh
python scripts/benchmark_qwen_replacement.py prepare
HF_HUB_OFFLINE=1 python scripts/benchmark_qwen_replacement.py live
HF_HUB_OFFLINE=1 python scripts/benchmark_qwen_replacement.py siglip
HF_HUB_OFFLINE=1 python scripts/benchmark_qwen_replacement.py qwen
python scripts/benchmark_qwen_replacement.py finish
```

`prepare` 会覆盖实验设计和抽帧；若需保留旧实验，请先另存整个实验目录。源码参考文件已保存在实验目录，复现需要本地模型缓存以及当前固定视频库。

- `experiments/qwen-replacement/design.json`：预先固定的设计、查询与标签。
- `live-siglip.json`、`siglip.json`、`qwen.json`：原始排序与逐次计时。
- `summary.json`：分组命中数和计时汇总。
- `trace-refinement.json`：全部截图的定位结果。
- `verification.json`：生产索引不变及适配检查。
- `provenance.json`：源视频、查询图片哈希、软件版本与模型版本。
- `reference/`：固定版本官方代码与来源。
