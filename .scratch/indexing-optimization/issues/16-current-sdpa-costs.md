用户要求重新分析当前上传后的耗时及继续优化的空间。只测量与分析，不切换新优化配置。

## Comments

- 2026-10-28：SDPA 切换后尚无新增正式上传记录。使用现有 35.44 秒源视频，在完整 44 视频库的隔离副本运行实际 process_job；包含原转码、帧提取、索引、Qwen 与本地发布，Qwen 已预热，不包含 HTTP 传输、排队和正式服务查询锁等待。
- 本轮插桩复测首次帧模型加载 56.54s、复用后 48.82s；前次未插桩部署验证为 55.14s / 39.02s。单次样本与系统状态有波动，不能把 48.82s 宣称为稳定水平或 SDPA 回退。
- 本轮复用分布：帧特征 16.86s（34.5%）、Qwen 准备编码 15.84s（32.4%）、帧索引 10.00s（20.5%）、转码 1.53s（3.1%）、发布校验 0.95s（2.0%）、Qwen 写入 0.023s，其他 3.62s（7.4%，其中整库复制 3.35s）。
- 帧提取内部：OWL 推理含 RPC/传输 11.39s，快速预处理 0.66s、人脸全流程 1.73s、帧读取 0.54s、向量元数据插入 1.25s。OWL 特征函数递归执行，inclusive 行不可直接求和；汇总只用不重叠组件或 exclusive 时间。
- Qwen 8 个片段 / 128 次 seek：定位 2.48s，VideoCapture 全部操作 2.64s；模型特征函数含预处理与推理 13.15s，未进一步拆分 GPU 前向。建议测按原帧编号顺序解码和有界预取，必须比对像素与时间定位，不能将全部 15.84s 视为可省解码时间。
- 索引单独探针：不驻留测试模型的完整 44 视频副本，原命令 3.80s；插桩运行实际两个 create_index 调用共 0.72s，进程体共 1.88s、外部墙钟 2.20s。与完整入库中 10s 不是同环境配对，不能承诺消除 9s。优先验证复用现有进程/轻量入口；再评估只追加新向量、CPU 建索引与 Qwen 编码重叠，并验证失败隔离和发布原子性。
- 复制冷/热分别 1.88s / 3.35s。可独立验证 APFS 克隆发布副本，避免每次复制完整数据；不使用硬链接替代隔离。首次等待可通过预热或按内存情况延长当前 600s 空闲驻留缓解，这会移动等待时间并增加内存占用。
- 人脸、Qwen 写入不是当前优先项；此前位置缓存无稳定收益；新 OWL 编译相对新 SDPA 的额外收益小且不叠加。降低抽帧率、分辨率或片段数量会改变检索覆盖，应单独评估，不作为默认方案。
- 正式项目、代码及人脸库指纹不变；本轮 2 次输出仍逐项匹配冻结的 SDPA 物体/人脸向量和元数据、Qwen 向量、4 个文本查询前十结果。实验项目已清理，剩余磁盘约 8.19 GiB；未部署新优化。
- 脚本 `experiments/indexing-optimization/profile_current_sdpa.py`、`profile_sdpa_index.py`；证据目录 `sdpa-current-profile-20261028/`，汇总 `summary.json`。官方能力依据：Faiss IndexIDMapTemplate.add_with_ids、OpenCV VideoCapture、Apple APFS clone 文档，链接已写入汇总。
