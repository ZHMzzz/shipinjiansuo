# 固定采样与 FP16，比较单视频像素预算

1. 冻结视频、查询和生产哈希。
2. 运行低/高/高/低对照，检查原始帧一致、dtype 一致、低预算复现生产向量。
3. 汇总耗时、内存、实际输入和分数；恢复服务并审计。

## Comments

- 用户要求单视频离线验证，仅改变像素预算；沿用之前明确允许的短暂停服和自动恢复授权。
- 2026-10-28 完成：同一视频低/高/高/低，FP16 与原帧哈希一致；每预算 4 次完整视频，中位数 8.58 → 21.27 秒，MPS driver 5.18 → 5.28 GiB。正确和错误查询分数均下降，单视频不能证明准确率改善。服务恢复，保护文件与发布指针未变。详见 [报告](../../../experiments/qwen-pixel-budget/REPORT.md)。
- 核实当前处理库有 FRAME_FACTOR=2 的预算换算，修正此前把 total_pixels 当成所有 RGB 帧像素简单相加硬上限的解释；本次实际输入为 16×256×448 与 16×384×640。
