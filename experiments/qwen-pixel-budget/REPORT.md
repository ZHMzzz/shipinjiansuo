# 单视频 Qwen 像素预算离线测试

2026-10-28。结论：本视频保持 FP16 与抽帧不变，仅将预算参数从 1048576 调至 7864320，解码与编码总耗时中位数从 **8.58 秒增加到 21.27 秒，约 2.48 倍（增加 148%）**。MPS driver 峰值只从 5.18 增至 5.28 GiB。正确和错误描述的分数都下降，本样本没有证明检索准确率提升。

## 样本与控制

- 视频：27 号 `抖音20261027-739727.mp4`，时长约 16.4 秒，门岗旁红帽人员坐着写字、另一人站立并摘帽。
- 4 个现有片段：0–8、4–12、8–16、12–16.4 秒；使用正式 `ActionEngine.encode_segment` 的 OpenCV 抽帧，每段固定 16 帧。
- 相同 Qwen3-VL-Embedding 2B、FP16、文本模板与权重。唯一模型处理参数差异是 `max_total_pixels`。
- 低/高/高/低顺序，4 个独立进程分别加载模型。各自用真实首片段热身，然后完整视频测两轮，每个预算共 4 次计时。文字向量固定为同一份。
- 核查所有轮次相同片段的原始 RGB 帧哈希完全一致；各进程文字向量完全一致；低预算视频向量与生产索引逐项一致，最大绝对误差为 0。
- 计时包含解码、取帧、缩放和 Qwen 编码，扣除了测试额外加入的原帧 SHA 计算；不含模型加载与热身，不是浏览器上传或完整入库时间。
- 六条查询在运行前固定，其中三个匹配视频，三个不匹配；参考此前视觉核查记录。未使用这些分数调门槛，也没有给其他视频混用不同预算做全库排名。

## 实际输入与速度

| 指标 | 低预算参数 1048576 | 高预算参数 7864320 |
| --- | ---: | ---: |
| dtype | FP16 | FP16 |
| 每片段帧数 | 16 | 16 |
| 每帧实际宽 × 高 | 256 × 448 | 384 × 640 |
| 16 帧实际 RGB 空间像素之和 | 1,835,008 | 3,932,160 |
| 每片段模型总输入 token | 980 | 2004 |
| 完整视频处理，4 次 | 8.18、8.64、8.53、8.95 秒 | 22.07、21.16、21.38、20.89 秒 |
| 中位数 | 8.58 秒 | 21.27 秒 |
| MPS driver 采样峰值 | 5.18 GiB（两进程一致） | 5.28 GiB（两进程一致） |

机器为本项目所在 Apple M5 / 32 GiB Mac。模型加载单次约 7.7–8.3 秒，另列于原始结果。内存是同口径进程采样值，不能与 RSS 相加，也不是所有视频场景的容量上限。

### 对“105 万像素上限”的纠正

此前把参数解释成“16 帧像素直接相加不超过约 105 万”，过于简化。当前安装的 `qwen-vl-utils` 的视频预处理使用以下换算：每帧像素上限的候选值为 `total_pixels / nframes * FRAME_FACTOR`，本版本 `FRAME_FACTOR=2`，然后再结合单帧上限、下限和尺寸对齐。

所以 **1048576 是处理库的预算参数，不是 16 帧原始 RGB 空间像素之和的硬上限**。本次低预算实际为约 184 万，高预算约 393 万；高预算也没有用满配置数值。原视频已转码，预算提高不能恢复转码之前丢失的细节。模型输入 token 还涉及视觉块及时间维度处理，不能直接与 RGB 像素数划等号。

源码位置为当前环境 `qwen_vl_utils.vision_process.fetch_video`；版本、路径和哈希见 `runtime-observation.json`。此次没有修改依赖库。

## 匹配分数

每条查询取该视频 4 个片段中的最高归一化向量内积分数，再对 4 次运行取均值。该分数**不是概率**；相同预算下本轮重复结果稳定。

| 查询 | 是否符合视频 | 低预算 | 高预算 |
| --- | --- | ---: | ---: |
| 红色安全帽写字 | 是 | 0.5957 | 0.5055 |
| 蓝色工服的人员在门岗旁，一人坐着写字、一人站着 | 是 | 0.5757 | 0.4784 |
| 站在门岗旁的蓝色工服人员头上没有戴安全帽 | 是，部分时段 | 0.6683 | 0.5822 |
| 红色安全帽骑自行车 | 否 | 0.5435 | 0.4368 |
| 户外慢跑 | 否 | 0.3558 | 0.2494 |
| 有人在游泳池里游泳 | 否 | 0.2809 | 0.2111 |

三个匹配描述的分数仍都高于三个不匹配描述，两种预算的六条分数顺序相同。“红色安全帽写字”与“红色安全帽骑自行车”的分差从 0.0522 增加到 0.0687，略有扩大，但不能由这一个差值推出全库误报减少。

错误描述分数下降的同时，正确描述也下降了；不能沿用某个固定门槛只看误报减少，忽略正确结果也可能被过滤。单个视频无法测跨视频排名、召回率或检索准确率，因此本次不报告准确率百分比。

## 决策意义与保护

此视频直接证明：即便保持 FP16，提高像素预算也能显著拖慢编码。因此上一轮变慢不能仅归因于 FP32。但本次单视频与上次全库不是同一统计样本，不能拿 3.47 倍除以 2.48 倍，反推精度的独立成本。

当前没有足够效果证据支持全库提高预算，建议先保持现有配置。若继续验证，应扩大到独立标注的小目标、文字和动作样本，再比较统一预算下的全库排名。
