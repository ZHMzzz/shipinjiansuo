# 复合查询有结果，单独动作查询为空：只读诊断

用户报告“红色安全帽骑自行车”有两个结果，“红色安全帽写字”有一个正确结果，而“骑自行车”没有返回第二个视频。2026-10-27 连续两次调用正式 `/mvp-api/library/search` 复现：分别是视频 `[27,32]`、`[27]`、`[]`。

`source scripts/env.sh && python experiments/query-specificity/reproduce.py` 在当前行为下按设计触发断言，指出复合查询的 27、32 不在单独动作结果中。它是捕获用户现象的诊断脚本，不表示当前向量检索原本承诺条件集合的单调关系，也不是新增产品回归规范。

## 原因

当前正式服务仍将完整查询编码成一个向量，未接入 DeepSeek 条件过滤。因此复合查询不是“红色安全帽”与“骑自行车”各自结果的交集。

当前过滤先检查最高分至少 0.52，再保留得分至少 `max(0.45, 最高分−0.08)` 的候选。只读原始 `/mvp-api/search` 得分与正式过滤规则复算完全一致：

| 查询 | 最高分 | 0.52入口门槛 | 后续候选门槛 | 返回 |
| --- | ---: | --- | ---: | --- |
| 红色安全帽骑自行车 | 0.543145（27） | 通过 | 0.463145 | 27、32 |
| 红色安全帽写字 | 0.595764（27） | 通过 | 0.515764 | 27 |
| 骑自行车 | 0.462051（32） | 不通过 | 整批清空 | 无 |

复合查询中视频32（抖音20261027-076258.mp4）的得分为0.479014，高于0.463145，因此跟随最高分视频通过。而单搜骑车时，32其实就是原始第一名，绝非被候选上限、分页或按视频合并截掉。它的0.462051低于0.52，所以连第一名也不返回。

写字视频27（抖音20261027-739727.mp4）的画面确实匹配红色安全帽部分，但整体嵌入给复合查询的分数不足以证明包含骑车动作。这是整体语义匹配的局限叠加统一门槛造成的现象，不能按关键字AND或概率解释这些分数。

只在保存的原始得分上跳过“最高分>=0.52”这一道门槛，仍保留现有候选门槛，会让“骑自行车”返回32。此为离线反事实诊断，**没有降低生产门槛**，也不证明全局降低门槛安全。

## 假设与证据

1. 整句匹配没有分别约束动作：现行服务代码及三个查询的不同原始得分支持。
2. 单独动作被绝对门槛清空：最高分0.462051、实际过滤函数复算及去掉该门槛的离线反事实均支持。
3. 候选截断或重复合并：被32在原始排名第一及正式路径全视频分组检索排除。直接调用正式API可复现，排除前端显示丢失。

用户本轮询问原因，因此未进入生产修复或调参；保留可复现诊断记录。前面的 DeepSeek 离线过滤可以处理部分复合误报，但它仍先通过原句基线门槛，**不能自动修复这次单独“骑自行车”的漏召回**。若调整，需要单独验证短动作查询的召回和误报权衡。

原始证据：`reproduction.json`、`raw-results.json`、`filter-probe.json`。未修改任何生产代码、页面、配置或索引，未重启服务。
