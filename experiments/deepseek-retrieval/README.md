# DeepSeek 自动拆分 → 现有 Qwen 片段检索：离线验证

2026-10-27。**能够减少误报，本轮没有新增删除已召回的已标注正确视频，但仍有明显误报，不能当作完整的复合条件判断。未接入正式页面。**

## 固定口径的主结果

以“查询—视频对”为统计单位；同一视频在不同查询下分别计数。复用前次已复核的部分正负例，不把未标注结果默认当作正确或错误。

| 查询组 | 基线已标注误报 | 自动过滤后 | 去掉误报 | 基线已召回的已标注正确结果 | 新增误删 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 原有 26 组查询 | 16 | 5 | 11（68.8%） | 20 | 0 |
| 6 段等义长描述 | 3 | 0 | 3 | 6 | 0 |
| 合计 32 组 | 19 | 5 | 14（73.7%） | 26 | 0 |

32 组总候选 **63 → 42**：删除了 14 个预先标注误报及 7 个原未标注候选。剩余 42 个包含 26 个已标注正确结果、5 个已标注误报和 11 个未标注结果。**5 不是全部残余误报的数量，73.7% 也不是精确率或完整召回率。** 段落与短句使用相同视频事件，不是完全独立的额外场景样本。

对被删除的全部 7 个未标注候选进行了抽帧复核，均得到不匹配查询的证据，未发现被误删的正确结果；详细原因见 `posthoc-review.json`。这些事后判断没有回填主统计，也未用于修改规则。抽帧不是逐帧穷尽标注，不能据此保证对所有视频均无误删。

## 方法与实际运行范围

1. `prepare.py` 在调用 API 前冻结原有 26 条查询、6 段等义长描述、3 个逻辑边界查询及判定规则。复用前次修正后的标注：27 是坐凳子在膝前写字，不是桌前；20 是仓库货架旁火情，不能直接认定为建筑工地。
2. DeepSeek Flash 沿用前次固定解析提示词，非思考、温度 0、JSON Output、最多 640 输出 token。模型只看到查询和提示词，**不看到人工拆分、正负例、视频或索引**。35 条主查询均生成合法结构，全部原始输出保存在 `parser-results.json`。
3. 当前库已从前次 **40 视频 / 129 片段变为 41 视频 / 135 片段**，新增视频 41 为脚手架施工。旧索引指纹检查阻止了旧分数复用，本轮重新编码全部 **142 个独立文本**，对当前全库实际向量做相似度计算，没有重建任何视频索引。
4. 先按当前正式规则筛整句候选：最高分至少 0.52；片段分至少 `max(0.45, 整句最高分−0.08)`。随后逐条件过滤；同一组的条件必须在**同一个原始片段**通过，不可跨片段拼接；备选组之间按 OR。最后每个视频仅保留原句得分最高的合格片段。
5. 条件门槛完全沿用前次人工拆分实验：`max(0.35, 该条件全库最高分−0.15)`。**没有用本次结果重新调参**。这些分数不是概率，库变化可能改变相对门槛。

程序不因某个条件的最高分低而擅自删除该条件；也不因样例标签为正就放宽门槛。当前这批保留视频的片段起止与原最佳片段一致；更换为同视频另一合格片段的通用逻辑另有数值测试。

前次“预期无结果”的标签只适用于原来 40 个已核查视频。新增 41 不自动继承负例标签；例如工地火情查询删除了 41，也未将它计入原标注口径的误报改善。

## 自动条件如何交给检索模型

主方案在不修改语义内容的前提下，固定把 `人物A` 等占位符替换为 `有人`、`工人A` 替换为 `工人`，再编码每条 `must`。不按样例手工改写或删条件。人物身份绑定仍留在原解析中，但检索执行只能近似检查同片段共现，不能证明同一人物满足多个条件。

同时在实验前声明了“原样直接编码”对照，及前次人工条件参考。基于当前相同索引、相同门槛，在原 26 组上的结果：

| 条件来源 | 16 个已标注误报中去掉 | 20 个已召回正例新增误删 |
| --- | ---: | ---: |
| DeepSeek 原样，带人物A占位符 | 10 | 0 |
| DeepSeek + 固定占位符替换（主方案） | 11 | 0 |
| 前次人工拆分参考 | 12 | 0 |

因此自动拆分接近本轮人工参考，但不是更准确。“人物A骑自行车”和“有人骑自行车”相似度不同：原样编码时红帽骑车仍留下视频 27；固定替换后剔除。人工参考在“工人坐在桌前低头书写”上额外剔除 27，自动条件没有做到。措辞变化本身会影响门槛结果。

另外，“锅里正在炒蔬菜”“有人翻越围栏”被解析为单项动作，基本没有增加额外过滤；正例保留不应全归因于新增条件机制。

## 为什么仍有误报

“户外慢跑”的室内跑步视频 7：

- 户外分数 **0.4006**，门槛 **0.3997**，仍被放行。
- 慢跑分数 **0.6245**，门槛 **0.4745**，通过。

条件拆分本身正确，但视觉向量没有足够区分室内/户外。街道行走视频 1、28 也得到足够高的慢跑分。

“红色安全帽骑自行车”的写字视频 27：戴红帽分数 **0.6408**，但骑车仅 **0.3713**，低于门槛 **0.3810**，因而正确剔除。这也是拆分能改善部分复合误报的原因。

“工人坐在桌前低头书写”的视频 27：虽然没有桌子，“工人坐在桌前”得分 **0.4860**，门槛 **0.4342**，仍错误通过。另一个措辞“工人戴着安全帽吸烟”仍返回写字视频 27，说明未穷尽标注的部分还存在误报，不能只关注主表中的 5 个。

## OR、否定、先后顺序与原本漏召回

3 条边界查询不混入上面的 32 条主指标：

- **“室内慢跑或者雪地滑倒”**：保留两个备选组并按 OR 执行，3 个候选仍为 7、17、26；保留已知正确 7、26，但误报 17 仍在。另一个已知正确视频 8 在整句基线就没进候选，新过滤不能补回。若要解决，需要另测分支分别召回并合并，不能把纯过滤实验当作已验证的分支召回。
- **“有人未佩戴安全帽”**：解析保留否定，但现有嵌入分数不是可靠的否定视觉证据。整条查询退回原基线，4 个候选保持不变，**没有宣称过滤有效**。已知正确视频 17 在当前基线就被排除。
- **“同一工人先摘安全帽，再坐着写字”**：解析有先后顺序，但同片段向量不能验证顺序。退回原基线，2 个候选不变；未标注其正确性，不计作成功正例保护。

`must_not`、`uncertain`、负向 `must`、明确先后顺序/人数/多人关系等同样按预先规则退回基线。`prefer` 不作为硬门槛。退回表示此实验未执行这些条件，**不是满足条件的认证**。

原有 26 组里，“有人坐在凳子上低头写字”的正确视频 27 也在基线阶段未召回；自动过滤不能修复。这些原本漏召回单列为 `baseline_missed_known_positive_ids`，不藏在“新增误删为 0”里。

## 性能

- 35 次 DeepSeek 主调用完整请求中位数约 **0.60 秒**。有固定提示词前缀缓存，不能当作所有网络和负载下的承诺。
- 6 条代表查询重新清空本地文字向量缓存后，逐条件编码中位数约 **0.14 秒**（2–4 条条件，范围约 0.09–0.22 秒）。
- 把这 6 条各自的 API 调用、整句编码、条件编码分别实测后相加，约 **0.52–0.80 秒，中位数 0.73 秒**；相对仅整句编码，组件加总新增耗时中位数约 **0.67 秒**。
- 这是组件加总，不是已接入页面的端到端搜索耗时；未包含线上并发排队、渲染等。条件向量门槛计算本身很轻。
- 离线进程模型加载约 9.01 秒，未计入热调用时间，正式服务没有因此重新加载或重启。

本轮 API 共 36 次成功调用（1 预热 + 35 主查询），未发送视频。运行器初次读取新数据格式时发现缺少 kind 字段，仅预热已完成；修复后保留该请求记录续跑，没有重复计分。首次索引指纹不一致时也在模型编码前终止，没有混用历史分数。OR 组主体编号检查在打分前修正并新增单元测试，未根据检索成绩调整规则。

## 复核、产物与生产隔离

- `design.json`：预先冻结查询、标签和规则；`prepare.py` 可重建设计。
- `parser-results.json`：DeepSeek 全部原始输出及 API 耗时；无密钥。
- `plans.json` / `plans.py`：实际执行的条件和退回原因；`plans-initial.json` 保留打分前 OR 主体编号检查修正的历史。
- `scores.json`：当前 135 片段、142 文本的实际得分、索引指纹和热编码耗时。
- `evaluate.py` / `evaluation.json`：不加载模型即可复算三种条件来源的逐查询结果、门槛、过滤前后视频和片段。
- `posthoc-review.json`、`review/media-*.jpg`、`new-video-review.jpg`：7 个被删未标注候选的抽帧复核证据。
- `test_logic.py`：5 项检查覆盖同片段 AND、不同组 OR、空组拒绝、OR 分支主体作用域、负向条件退回。
- `production-unchanged.json`：6 条正式接口只读查询与离线基线逐一一致；例如线上仍返回户外慢跑 5 条、红帽骑车 3 条，证明实验过滤没有接入。

正式服务 PID 75954、当前发布指针和 Qwen 索引 SHA-256 在运行前后保持一致。没有修改 `scripts/`、页面或正式配置，未重启服务。所有修改仅在本实验目录和对应 `.scratch` 文档。

复算：项目根目录先 `source scripts/env.sh`，运行 `python experiments/deepseek-retrieval/evaluate.py`；测试运行 `python experiments/deepseek-retrieval/test_logic.py`。已有模型/API原始结果不得覆盖；新增实验应使用新输出目录。API 凭据只读环境变量或关闭回显的终端输入，不存储在文件中。

本轮建议：可以继续作为低成本补充过滤方案验证，尤其是红帽骑车这类误报；目前证据不足以保证通用复合条件准确，也不能替代未佩戴安全帽、同一人关系和时间顺序的视觉核验。按要求维持离线状态。
