# Qwen 片段统一到 WISE：实施与验证

2026-10-28，已完成并启用。正式服务模型已预热，仍为 41 视频、135 个 Qwen 片段。

## 变更

- 新视频的 Qwen 向量直接写入 WISE 元数据、特征文件与搜索索引，活动库不再保存 `action-index`。
- 自然语言检索继续使用原有 WISE 排序；人物组合查询从同一套 WISE 片段向量建立内存视图，融合、门槛和排序不变。
- 视频列表的片段数、状态统计和补建改为读取 WISE；完整数据不重新编码，新视频只编码缺少的部分。
- WISE 帧模型自动发现期间暂存 Qwen store，finally 恢复，避免上传删除掉唯一向量来源。命令行入库入口也使用同一暂存保护。
- 删除同时清理 WISE 数据与历史旧格式；支持删除到空库。旧格式读取只为迁移/历史兼容保留。
- `qwen-encoding.json` 只记录编码参数、向量维度和媒体签名，不另存片段向量。WISE 自身的标准特征文件和检索索引仍保留。

编码参数完全不变：Qwen3-VL-Embedding 2B、FP16、`max_total_pixels=1048576`、8 秒窗口/4 秒步长、现有 OpenCV 每片段 16 帧。没有切换到原版 FP32、原版抽帧或高像素预算，也没有改页面。此次是统一存储维护，不声称改善准确率或明显提速。

## 验证

**67 项测试通过**，命令为 `source scripts/env.sh` 后 `python -m pytest tests -q`。覆盖已有检索/上传/删除测试，以及迁移保留向量与 ID、迁移失败不发布、缺少视频增量补建、旧格式首次启动、暂存失败恢复、损坏 native 数据不退回旧快照、参数/时间覆盖校验、人物组合查询与列表片段计数。

独立项目副本执行真实 WISE 上传流程：

1. 迁移副本的已有 135 个片段，向量与 ID 完全一致，不调用视频编码。
2. 上传一条 1.4 秒测试视频，实际转码、OWLv2/人脸提取、Qwen 编码及发布。只编码新增的 1 个 Qwen 片段，41/135 → 42/136，已有 135 个向量及 ID 不变。
3. 删除该测试视频及索引，清理 614 个新向量（含 1 个 Qwen 片段），恢复 41/135。原始来源视频未修改，删除无待清理任务。
4. 对完整索引执行补建检查，直接就绪，没有额外编码。测试工作目录已删除，测试视频未进入正式库。

正式迁移后逐项核对：

- 135 个向量与迁移前逐元素一致，媒体、窗口与编码设置一致。
- `media`、`source_collections`、`vectors`、`featured`、人脸和物体扩展元数据表的所有行一致，包括向量 ID。
- 人脸、OWLv2 索引、缩略图数据库和人物登记库的文件 SHA-256 一致；旧发布文件保持不变。
- 正式 `/mvp/` 返回 200；Qwen 已加载，状态为 ready。
