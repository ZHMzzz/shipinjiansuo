# 查询条件自动拆分：小型文本模型与 DeepSeek Flash 离线对照

测试日期：2026-10-27。仅拆分文字查询，未接入正式页面，未用这些结果过滤真实视频。

**本轮 DeepSeek Flash 明显优于本地 Qwen3-0.6B 非思考基线：24 条中严格通过 22 条，完整请求中位数 0.59 秒；本地基线严格通过 2 条，中位数 1.15 秒。** 此结论限于本轮固定提示词、配置和诊断集，不能推广为所有小型模型均不可用，也不是实际视频检索准确率。

## 方法与评分

先保存 `design.json`，固定 12 条短句、12 段描述及逐条参考判定点；推理时只发送统一提示词与查询，参考判定点不传给模型。覆盖场景与动作、颜色归属、同人与不同人、AND/OR、时间先后、否定、数量、偏好、指代歧义、没有有效线索等情况。短句中也包含复杂条件，不能从两组成绩推断段落一定比短句简单或更难。

- **结构正确**：原始输出直接通过 JSON 解析且字段、数组元素类型均符合约定。未静默修复尾逗号、Markdown 代码围栏、缺失字段等问题。
- **严格通过**：结构正确且全部预先规定的语义与拆分粒度要求通过。不能只保证关键词都出现，逻辑错误、主体绑定错误、丢失动作、额外硬约束均失败。
- 逐条语义评分由同一代理人工式审阅完成，允许同义措辞，不是独立人工标注或盲评；原文及审阅理由全部保存，可复核。
- 格式采用 `groups` 表示备选，每组的 `must` 同时成立，`must_not` 排除、`prefer` 偏好、`relations` 关系、`uncertain` 歧义。条件暂为自然语言字符串，**不是可直接执行的完备逻辑树**。例如否定事实也可能被保存在 `must` 文本中；后续仍需类型化及校验。
- 同一组中重复人物名指同一对象；不同人物变量是否为不同人应由明确关系决定，不能忽略 `uncertain` 后直接强制不等。
- 另外选 4 条查询各重复 2 次，共 8 次重复，不计入 24 条主测试准确率。

## 配置

本地使用官方 `Qwen/Qwen3-0.6B`，revision `c1899de289a04d12100db370d81485cdf75e47ca`，Apple M5 / 32 GiB，PyTorch 2.8.0、Transformers 4.57.6，MPS FP16 / SDPA，`enable_thinking=False`、贪心解码、最多 640 新 token。为复现选择贪心，此处不是对官方推荐采样配置或思考模式的全面调优。初次进程加载 4.20 秒，第一条预热 1.90 秒；系统文件缓存未清空，不将其称为严格冷磁盘加载。

线上使用用户指定的 `deepseek-flash`，端点 `https://api.deepseek.com/chat/completions`，显式关闭思考，温度 0，`response_format=json_object`，最多 640 输出 token，非流式、串行、同一 HTTP 客户端复用连接，不自动重试。官方文档当日将该别名映射到 DeepSeek-V4.1-Flash-1017；API 响应返回的模型名是 `deepseek-flash`，不声称固定了不可变权重版本。

两者使用完全相同的主测试输入和提示词，但 **API 有额外 JSON Output 约束，本地没有语法约束解码**，因此这是两种实际可用配置的比较，不是严格控制所有变量的纯模型排名。两种 tokenizer 不同，640 token 不代表同样字符数；本轮均未截断。

凭据通过关闭回显的终端输入，仅用于请求进程内存，不写入本目录、代码、报告或 Git。线上仅发送本测试人工构造的查询，不发送视频、索引或参考答案。

## 主结果

| 配置 / 查询 | 结构正确 | 严格通过 | 耗时中位数 | P95 | 范围 |
| --- | --- | --- | --- | --- | --- |
| Qwen3-0.6B / 12 短句 | 0/12 | 0/12 | 0.95 秒 | 1.61 秒 | 0.66–1.82 秒 |
| Qwen3-0.6B / 12 段落 | 3/12 | 2/12 | 1.24 秒 | 2.20 秒 | 0.70–2.33 秒 |
| DeepSeek Flash / 12 短句 | 12/12 | 12/12 | 0.58 秒 | 0.80 秒 | 0.48–0.94 秒 |
| DeepSeek Flash / 12 段落 | 12/12 | 10/12 | 0.61 秒 | 0.82 秒 | 0.43–0.85 秒 |

DeepSeek 合计严格通过 **22/24（91.7%）**；本地合计 **2/24（8.3%）**。严格通过率不是逐词理解率，尤其本地存在大量格式失败；即使放宽格式，也能直接观察到 OR 变 AND、将备选场景改为排除条件、把必需否定变成偏好等语义错误。

API 耗时含本机到服务的完整请求等待及响应解析，不含后续本地向量检索、视频核验和页面渲染。首个 API 请求 0.83 秒。主测试固定提示词存在供应商前缀缓存命中，不能将本轮 0.59 秒视为无缓存、高并发或其他网络条件的延迟承诺。小样本 P95 仅为描述统计（线性插值），不是服务 SLA。

## DeepSeek 两个未通过样例

1. **p07：指代不明，但动作本身确定。** 原文有两名工人，后来“他骑上自行车离开了”，不确定是谁骑车。模型正确记录两人和指代歧义，却把整个骑车离开事件仅放在 `uncertain`，`must` / `relations` 中漏掉了“随后有人骑车离开”这个确定条件。检索时可能放过根本没有骑车的画面。
2. **p10：拆分粒度不足。** 原文要求同一工人先放下箱子、然后坐在凳子上写字。模型保留了主体、动作含义和顺序，但将“坐在凳子上写字”留为一个条件，没有按预先标准拆成坐凳子与写字。此项是细粒度拆分失败，不是场景含义理解错误；不可为抬高成绩在看完输出后放宽标准。

可以针对这两点改提示词，但本轮没有用主测试答案反复调优并重新报告为独立准确率。下一轮应新增未见样例，检查修复是否有效。

## 本地失败排查与重复稳定性

首轮发现大量 JSON 错误后，冻结了 4 条抽查查询（s02、s04、p01、p08），做探索性控制：

| 控制 | 结构正确 | 全部语义要求通过 |
| --- | --- | --- |
| 原提示词 / FP16（主测试对应 4 条） | 0/4 | 0/4 |
| 原提示词 / BF16 | 1/4 | 0/4 |
| 简化提示词 / FP16 | 0/4 | 0/4 |
| 简化提示词 / BF16 | 0/4 | 0/4 |

BF16 的 p08 恢复了两个正确备选，但仍丢失货架偏好。简化提示词还出现了擅自生成嵌套类型和人物职业等错误。有限控制未解决主要问题，不足以排除所有推理/提示词因素；未测试本地思考模式、量化版本、语法约束或更大文本模型。控制样例是在观察主测试后选择，不能当作独立留出集。

本地 8 次重复均原文一致，但一致地重复错误不等于可靠。DeepSeek 8 次重复均语义等价，7 次原文一致；另 1 次只改变了“不确定是否同一人”的措辞。

本地进程记录的 MPS driver 分配峰值约 7.01 GiB，包含分配器/运行缓存，不能当作模型权重大小或最低显存要求；RSS 约 0.36 GiB 与统一内存统计可能重叠，不能相加。系统 swap 峰值约 22.34 GiB，机器同时运行正式服务，不能把全部 swap 归因于此模型。

## API 用量与成本估算

33 次调用（1 次预热、24 主测试、8 重复）均 HTTP 200，无空输出、截断或返回思考内容，无重试。总输入 14,263 token，其中缓存命中 8,192、未命中 6,071；总输出 1,821 token。

按测试当日官方人民币单价，整批估算 **0.0135–0.0270 元**（空闲/高峰时段两种费率），这是根据 usage 的估算，未读取账户账单。实际部署的提示词长度、缓存命中和模型价格变化会影响成本。

## 对项目的含义

下一步更值得验证 **DeepSeek 解析文字 → 本地 Qwen 片段检索 → 条件检查**，而不是将本轮 0.6B 配置直接接到页面。线上调用一次解析整段查询，不必对每个视频调用文本解析 API。

拆分正确仍不能证明片段满足条件。尤其“未佩戴安全帽”、同一人同时满足多属性、先后动作，现有嵌入相似度不等于逻辑或视觉核验；不能简单对否定描述的向量打分就宣称识别了未佩戴。本轮不改变此前 Instruct 离线实验的视觉可靠性结论，也没有测实际候选误报/漏报变化。

接入前还需要：固定可执行的条件结构、为已知能力不足的条件规定处理方式、用新查询及真实片段验证误报和误删、评估完整搜索耗时。当前维持离线状态。

## 文件与复现

- `prepare.py` / `design.json`：推理前冻结的主提示词、查询和评分点。
- `run.py` / `results.json`：本地全量原始输出、分段耗时和资源记录。
- `design-control.json`、`design-simple.json`、`results-*-control.json`、`results-simple-*.json`：事后探索性控制。
- `run_api.py` / `api-settings.json` / `results-deepseek.json`：API 参数及完整输出、usage 和请求耗时；没有认证头。
- `review.json` / `review-deepseek.json`：每条审阅理由。
- `summarize.py`、`summarize_api.py`、`summary*.json`：可重算统计。

在项目根目录执行 `source scripts/env.sh` 后，可运行相应脚本。运行器拒绝覆盖已有结果；新试验应指定新的本地输出文件，或在独立实验目录复用 API 运行器并设置新的输出路径。API 运行器从环境变量 `DEEPSEEK_API_KEY` 或隐藏终端提示读取凭据。不要把密钥作为命令行参数或写进脚本。

运行前后正式服务 PID 均为 75954，`projects/demo` 发布指针和 action-index 文件 SHA-256 完全一致。没有改动在线查询、页面、模型预加载或视频索引。
